> 주의: 현재 GitHub Release `v1.0.12`에는 기준일 이후의 로컬 수정이 포함되지 않았을 수 있다.

## 1. 상태 표기

| 상태 | 의미 |
|---|---|
| ✅ 구현 완료 | 실제 화면과 동작이 연결되어 있으며 일반 실행 경로에서 사용할 수 있음 |
| 🟡 부분 구현 | 핵심 코드는 있으나 기기, 권한, 서버 또는 추가 검증이 필요함 |
| 🧪 데모 구현 | 심사용 목업 데이터 또는 데모 상품으로 동작함 |
| ⛔ 미구현 | 화면만 있거나 아직 실제 동작이 없음 |

## 2. 서비스 개요

슬립레디는 교대근무자의 날짜별 근무표, 수면 기록, 생활 습관, 현재 컨디션과 피부 상태를 함께 읽어 다음 정보를 제공하는 Flutter 기반 iOS·Android 앱이다.

- 개인별 권장 취침·낮잠 시각
- 필요 수면량과 실제 수면량의 차이
- 누적 수면 부족 추정
- 카페인, 빛 노출, 조명, 취침 준비 행동 넛지
- 주간·월간·근무루틴별 수면 리듬 시각화
- Gemini 기반 수면·생활 패턴 분석과 행동 추천
- 수면 상태를 우선 반영한 피부 루틴과 AAC 데모 제품 추천

## 4. 구현 완료 기능

### 4.1 앱 시작과 세션 복원

- ✅ 앱 시작 시 Supabase 초기화를 시도한다.
- ✅ 로컬 `SharedPreferences` 상태를 복원한다.
- ✅ 유효한 Supabase 세션이 있으면 사용자 프로필과 상태 기록을 복원한다.
- ✅ 온보딩 프로필이 이미 있으면 로그인·온보딩을 건너뛰고 홈으로 이동한다.
- ✅ 로그인만 완료하고 온보딩을 끝내지 않은 사용자는 온보딩으로 이동한다.
- ✅ 앱 이름, Android·iOS 표시 이름과 런처 아이콘이 `슬립레디`로 설정되어 있다.
- ✅ Pretendard와 Jua 폰트를 앱에 포함한다.

### 4.2 로그인·회원가입·게스트

- ✅ 이메일과 비밀번호를 이용한 Supabase 로그인
- ✅ 이름, 이메일, 비밀번호를 이용한 Supabase 회원가입
- ✅ 비밀번호 확인 및 입력값 검증
- ✅ 필수 개인정보 수집 동의
- ✅ 선택 AI 국외 이전 동의
- ✅ 이메일 인증이 필요한 경우 인증 메일 안내 팝업 표시
- ✅ Supabase 오류 메시지를 사용자에게 스낵바로 표시
- ✅ 로그인 처리 중 로딩 상태 표시와 중복 요청 방지
- ✅ 회원가입 화면과 개인정보 처리방침 화면 연결
- ✅ Supabase 설정 없이 사용할 수 있는 `게스트로 계속하기`
- ✅ 게스트도 로컬 AI 동의를 켜고 AI 답변 기능 사용 가능
- ✅ 로그아웃 시 Supabase 세션과 로컬 상태 초기화
- ✅ 게스트 로그아웃 시 데이터 삭제 가능성 확인 팝업 표시
- ✅ 로그인 화면에 슬립레디 브랜드 타이포그래피, 그라데이션, 시계·`Zzz` 배경 장식 적용

### 4.3 온보딩과 개인 프로필

- ✅ 병원별 데이·이브닝·나이트 근무 시작·종료 시각 입력
- ✅ 24시간 형식의 시간 선택 UI
- ✅ 근무지 밝기 선택
- ✅ 침실 암막 환경 선택
- ✅ 쉬는 날 자연스러운 기상 성향 선택

- ✅ 하루 카페인 섭취량 선택
- ✅ 피부 타입 선택

- ✅ 알림 권한 필요 이유 안내
- ✅ iOS·Android 알림 권한 실제 요청
- ✅ Android에서 정확한 알람과 배터리 최적화 예외 필요성 안내

## 5. 부분 구현 또는 환경 의존 기능

### 5.1 실제 웨어러블 연동

- 🟡 HealthKit·Health Connect를 읽는 코드는 구현되어 있다.
- 🟡 실제 값은 워치가 건강 플랫폼에 데이터를 기록하고, 사용자가 읽기 권한을 허용해야 나타난다.
- 🟡 iOS 시뮬레이터에서는 실제 Apple Watch 데이터 연동이 불가능하므로 데모 데이터를 사용한다.
- 🟡 Android는 Health Connect 설치·지원 여부와 Galaxy Watch의 Samsung Health 연계 상태에 영향을 받는다.
- 🟡 실제 기기 조합별 장기간 검증과 스토어 배포 환경 검증은 별도 필요하다.
- 🟡 Health Connect의 일광 노출 데이터는 제공되지 않아 Android에서는 해당 신호가 없다.

### 5.2 건강 데이터 서버 저장

- 🟡 `health_daily_metrics` 스키마와 데모 계정 복원 경로는 존재한다.
- 🟡 일반 사용자의 실제 HealthKit·Health Connect 요약은 현재 앱 로컬 상태에 저장된다.
- 🟡 일반 사용자의 실제 건강 요약을 Supabase에 업로드하는 전체 동기화는 연결되지 않았다.
- 🟡 원본 건강 샘플은 의도적으로 서버에 저장하지 않는다.

### 5.3 근무표 서버 저장

- 🟡 `roster_entries` 스키마와 데모 계정 조회 경로는 존재한다.
- 🟡 일반 사용자가 업로드·편집한 근무표는 현재 로컬 저장이 중심이다.
- 🟡 일반 사용자 근무표를 Supabase에 자동 업서트하고 다른 기기에서 복원하는 경로는 미완성이다.

### 5.4 알림

- 🟡 실제 넛지 예약은 구현되어 있다.
- 🟡 Android 정확 알람 허용 설정 화면을 직접 여는 동작은 없다.
- 🟡 Android 배터리 최적화 예외 설정 화면을 직접 여는 동작은 없다.
- 🟡 알림 탭 후 특정 화면으로 딥링크하는 처리와 반응 로그 저장은 없다.
- 🟡 설정의 행동 알림·주간 리포트 알림 토글은 현재 화면 내부 상태 중심이며 실제 예약 정책과 완전히 연결되지 않았다.

### 5.5 AI

- 🟡 Gemini 호출은 인터넷, Supabase Edge Function, `GEMINI_API_KEY` 상태에 의존한다.
- 🟡 서버 응답이 실패하면 앱 기능은 유지되지만 생성형 응답 대신 로컬 폴백이 표시된다.
- 🟡 AI 결과는 웰니스 참고 정보이며 의료 진단이 아니다.
- 🟡 AI 모델명과 프롬프트는 Edge Function 배포본이 로컬 소스와 동일해야 한다.

### 5.6 인증·계정

- 🟡 이메일 인증 여부는 Supabase 프로젝트 설정에 따라 달라진다.
- 🟡 비밀번호 찾기·재설정 화면은 없다.
- 🟡 소셜 로그인은 없다.
- 🟡 회원 탈퇴와 서버 데이터 일괄 삭제 기능은 없다.
- 🟡 관리자 페이지와 관리자 계정은 없다.

### 5.7 엑셀 파싱

- 🟡 Railway 파싱 서버와 인터넷 연결이 필요하다.
- 🟡 병원마다 다른 복잡한 병합 셀·암호화 파일·비표준 양식은 파싱 실패 가능성이 있다.
- 🟡 파싱 서버 장애 시 직접 패턴 입력을 사용해야 한다.

## 10. 현재 알려진 제약과 주의점

- 현재 앱 버전은 `1.0.12+13`이다. 다음 릴리스에서는 버전명과 APK 파일명을 함께 올려야 한다.
- 최신 로컬 수정은 기존 GitHub Release `v1.0.12` APK에 자동 반영되지 않는다.
- 공개 저장소에는 Supabase `service_role` 또는 Gemini 비밀 키를 넣으면 안 된다.
- 모바일 앱에는 Supabase publishable key만 포함할 수 있다.
- Gemini 비밀 키는 Supabase Edge Function 환경 변수로만 관리해야 한다.
- 실제 웨어러블 데이터 품질은 워치 착용, 건강 앱 동기화, 권한과 제조사 앱 설정에 따라 달라진다.
- 수면 부족과 권장 취침은 의료 진단이 아니라 계산 모델 기반 참고값이다.
- 실제 AAC 상품 연동 전에는 모든 상품 카드가 데모임을 유지해야 한다.
- 개인정보 처리방침은 실제 운영·보관 정책 확정 후 법무 검토가 필요하다.
